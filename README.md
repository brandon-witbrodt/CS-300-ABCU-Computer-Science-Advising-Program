# CS-300-ABCU-Computer-Science-Advising-Program
Project Overview
This repository contains two portfolio artifacts from CS 300. Project One analyzes the runtime and memory requirements of vectors, hash tables, and binary search trees. Project Two implements a C++ course advising program using a binary search tree to store course information, look up prerequisites, and print courses in alphanumeric order.
Reflection
What was the problem you were solving in the projects for this course?
The goal of these projects was to develop a program that academic advisors could use to access information about the courses in a computer science program. The program needed to read course data from a file, organize the courses, print the complete course list in alphanumeric order, and display an individual course with its prerequisites. In Project One, I evaluated different data structures and planned how the program would work. In Project Two, I implemented the design in C++.
How did you approach the problem? Consider why data structures are important to understand.
I started by comparing vectors, hash tables, and binary search trees based on their runtime performance, memory usage, and suitability for the program's requirements. A vector is straightforward to use, but searching through it can require checking every course. A hash table offers efficient average-case lookups, but printing courses in order requires a separate sorting step. I chose a binary search tree because an in-order traversal prints the courses in alphanumeric order without additional sorting. This process helped me understand that choosing a data structure affects not only performance but also how the rest of the program is designed. I also learned that an unbalanced binary search tree can perform poorly if its nodes become skewed, so no single data structure is automatically the best choice in every situation.
How did you overcome any roadblocks you encountered while going through the activities or project?
One of the main challenges in the design was making sure course information was valid before it could be used. A prerequisite might refer to a course listed later in the input file, so checking prerequisites as each line was read would not always work. I addressed this by first loading the courses and then checking that every referenced prerequisite existed. I also separated tasks such as parsing input, searching the tree, printing courses, and displaying the menu into functions. Breaking the program into smaller pieces made the logic easier to follow and helped me work through the requirements individually.
How has your work on this project expanded your approach to designing software and developing programs?
These projects showed me the value of evaluating requirements and algorithm efficiency before starting to code. In Project One, I used Big O notation to compare the time and memory costs of different structures, including their worst-case behavior. In Project Two, I carried that analysis into an actual implementation. The experience reinforced the importance of designing around what the program needs to do instead of choosing a familiar data structure without considering the tradeoffs.
How has your work on this project evolved the way you write programs that are maintainable, readable, and adaptable?
I have become more aware of how much program organization matters. In Project Two, I used a Course structure to keep related data together and a BinarySearchTree class to manage the tree's operations. Functions handle individual responsibilities, including loading the file, validating prerequisites, searching, and printing the course list. The program also checks for missing or duplicate course information and invalid prerequisites instead of continuing with unusable data. These choices make the code easier to read, troubleshoot, and modify. In the future, I can apply the same approach by separating responsibilities, validating input, and choosing data structures based on the needs of the application.
